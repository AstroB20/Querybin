A curated query gateway

Share data, not
database access

Your DBA builds vetted queries in a web page and publishes each one as a safe, read-only endpoint. Engineers call the endpoints — they never get credentials, never touch the database, never send SQL. A menu of approved queries instead of the keys to the kitchen.

SELECT owner, balance FROM accounts WHERE balance > ?
GET /api/rich-accounts?minimum=1000

01What it does

You pick a table, columns, filters and a sort order in a visual builder — never writing SQL. The builder validates everything against your real database and publishes a safe, parameterized endpoint. Callers never send SQL; they only fill in the values you exposed.

🧰

Visual query builder

Choose a table, columns, filters and sort. Preview the generated SQL and rows before you publish.

🔑

Caller parameters

A filter can be a fixed value or a parameter the caller supplies, like ?minimum=1000. Optional ones drop out when omitted.

🛡️

Safe by construction

Table and column names must exist in your live schema, and every value is bound as a statement parameter.

02Two planes

Two services, split along a security boundary. The control plane is the DBA's private tool for designing and publishing queries — it needs a login. The data plane serves the published APIs engineers call, and it only ever reads the database.

Engineers can only reach the data plane, on a network with no access to the publish endpoints or the metadata — the boundary is enforced by deployment, not just an in-app check. The runtime fetches definitions over HTTP, so your API definitions stay in a separate store a published API can never reach.

04The time machine

Every publish is saved as an immutable version. Old versions keep serving at /api/name/v/1, you can diff any two, and rolling back just republishes an old version as the newest — nothing is ever rewritten.

v1 — owner, balance  first publish
v2 — added city filter  still callable at /v/1
v3 — rolled back to v1  note: "Rolled back to version 1"

05Grab a ready-to-run command

The cURL builder fills in your parameter values and generates a copy-paste command for bash or PowerShell, optionally pinned to a version.

cURL builder
$
{ "api": "rich-accounts", "version": 3, "count": 2, "data": [ { "owner": "Ishita Rao", "balance": 127500.00 }, { "owner": "Meera Nair", "balance": 48900.75 } ] }

06Add it to any app

It ships as Docker images. Point it at an existing PostgreSQL or MySQL database with a read-only account. The DBA keeps the builder private; engineers reach only the runtime.

# 1. configure your database + admin password in .env
Copy-Item .env.example .env

# 2. start the two services
docker compose up --build -d

# 3. DBA opens the builder and signs in
start http://localhost:8080/

# engineers just call the published API
curl http://localhost:8081/api/rich-accounts?minimum=1000
